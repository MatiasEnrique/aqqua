# Tickets: Agentic Board

Vertical-slice tickets for the Agentic Board feature. Source spec: `docs/plans/agentic-board.md` — read it before starting any ticket; it fixes the domain vocabulary (board, step, card, position vs status, artifact, continuation mode) and the decided semantics.

Work the **frontier**: any ticket whose blockers are all done. After "Statuses in place" the frontier is wide — Recovery, Manual gates, and Card detail are mutually independent.

## Board definition end-to-end (CRUD + editor)

**What to build:** A user can create and edit an Agentic Board inside a project: named steps between the built-in To-Do and Done columns, each step carrying a prompt template, an agent-profile reference (reusing the existing agent-profiles system), and a continuation mode (`auto`/`manual`). Definitions persist through the standard event → projection pattern and stream to the client over the existing WS subscription machinery.

**Blocked by:** None — can start immediately.

- [ ] A board can be created, renamed, and its steps added/edited/reordered/removed from a board-editor UI
- [ ] Step editor exposes prompt template, profile picker, and continuation mode
- [ ] Board definition survives server restart and streams live to a second client
- [ ] Board events are appended to the orchestration event store and projected, consistent with existing aggregates

## Cards in the backlog

**What to build:** A user can create cards on a board. The creation dialog's parameter form is generated by scanning all step prompt templates for `${placeholders}` (reserved names like `${artifact:*}` excluded). New cards land in To-Do — no worktree is created yet. The board view renders To-Do, the step columns, and Done, with cards showing title and parameter chips.

**Blocked by:** Board definition end-to-end.

- [ ] Adding `${new_param}` to any step template adds a field to the card-creation form without further configuration
- [ ] Created cards appear in To-Do with a placeholder title derived from parameter values
- [ ] Creating a card performs no worktree or git operations
- [ ] Board view renders the run table — To-Do section rows with Start, in-flight rows with position track + status badge, Done section rows with Archive — and streams card additions live (per Design source)

## Release → pipeline happy path → Done

**What to build:** Starting a card runs the whole pipeline unattended. Start creates the card's worktree + branch, snapshots the board definition onto the card, and spawns a fresh top-level thread for step 1 with the rendered prompt: parameter substitution, artifact-path injection (per-worktree artifact directory in the state dir), and an appended instruction to call the new `board_complete` MCP tool. On `success` from an `auto` step, the card advances to the next column; after the last step it reaches Done. `${artifact}` / `${artifact:step-name}` placeholders in later steps resolve to the paths of earlier artifacts.

**Blocked by:** Cards in the backlog.

- [ ] Start creates worktree + branch and moves the card into step 1 with a `running` status badge
- [ ] Step threads are ordinary threads (visible in the sidebar, chat-capable) running in the card's worktree
- [ ] `board_complete({outcome: "success"})` advances the card; the last step's success lands it in Done
- [ ] Artifacts are written to the deterministic per-worktree path and later steps receive the correct paths via explicit placeholders only
- [ ] Editing the board mid-flight does not change a released card's behavior (snapshot semantics)
- [ ] A 2-step board demonstrably runs a card to Done with no user interaction

## Statuses in place (needs-input / failed)

**What to build:** Non-success outcomes badge the card where it sits — the card never changes column for status reasons. A turn that completes without calling `board_complete`, a `blocked` outcome, or a pending permission approval → `needs-input`. A turn error → `failed`. Badges render on the card in its column and stream live.

**Blocked by:** Release → pipeline happy path → Done.

- [ ] Turn completed without `board_complete` → card shows `needs-input` in its current column
- [ ] `board_complete({outcome: "blocked"})` → `needs-input`
- [ ] Turn error → `failed`
- [ ] A pending permission approval surfaces as `needs-input`
- [ ] No status transition ever changes the card's column

## Recovery: Cancel, Retry, chat-to-resume

**What to build:** Every stuck or running card can be recovered without leaving the model. Cancel interrupts the running step's turn (→ `cancelled`, card stays in place). Retry discards the step's thread and spawns a fresh one from the same snapshot template and inputs. Chatting into a flagged step's thread works like any conversation — when the agent eventually calls `board_complete`, the flow resumes normally.

**Blocked by:** Statuses in place.

- [ ] Cancel interrupts the turn and badges the card `cancelled` in place
- [ ] Retry replaces the step thread and re-enters `running` from the same rendered prompt
- [ ] A user turn sent into a `needs-input` step's thread that ends in `board_complete(success)` advances the card
- [ ] All three paths are reachable from the card's actions in the board UI

## Manual continuation gates

**What to build:** A step with `manual` continuation pauses the card in place on success (`paused` status) instead of advancing. The user reviews — and optionally edits — the step's artifact file, then hits Continue to advance. The next step reads whatever is on disk at continue time. A manual gate on the last step pauses before Done with identical semantics.

**Blocked by:** Statuses in place.

- [ ] `manual` step success → `paused` badge, card stays in its column
- [ ] Continue advances to the next step (or Done); Retry remains available while paused
- [ ] Artifact edits made while paused are what the next step receives
- [ ] `paused` counts toward the board's "needs you" surfacing alongside `needs-input`

## Card detail: timeline, sub-agent tree, artifact viewer/editor

**What to build:** Opening a card shows everything it owns, per the three V3-i1 artboards (per Design source): a selectable tree in the middle rail — steps as top-level rows (status, elapsed · cost) with sub-agent threads, the step's diff, and its artifact as leaves — and a single right-hand detail slot that renders the selection using the app's existing chat surface. Selecting a step thread shows its rendered prompt (with resolved `${artifact}` chips), turns, and pending question; selecting a sub-agent thread shows its own transcript (send-only composer — it can't move the card); selecting an artifact shows the document live-editable inline with provenance (written by / read by), covering the paused-review flow. Card actions ride the composer's primary-action slot (`Resume ⌄` split: resume / retry fresh / mark done / cancel).

**Blocked by:** Statuses in place.

- [ ] The three selection states match the three dark artboards (step thread / sub-agent thread / artifact)
- [ ] Detail pane and composer are the app's existing chat surface and `ChatComposer`, not bespoke components
- [ ] Sub-agents appear as leaves under the step that spawned them and cannot advance the card
- [ ] Artifacts are live-editable in place; edits are on disk when the step resumes
- [ ] Failure/blocked notes render on the step that produced them

## Done semantics + Archive

**What to build:** Done keeps everything — worktree, branch, artifacts — so PR follow-ups can be pushed from the step threads. An explicit Archive action on a Done card deletes the worktree (existing worktree-deletion machinery) and the card's artifact directory.

**Blocked by:** Release → pipeline happy path → Done.

- [ ] Reaching Done performs no cleanup; step threads remain usable
- [ ] Archive deletes the worktree and artifact directory and marks the card archived
- [ ] Archive is only offered on Done cards in v1

## AI-generated card titles

**What to build:** Card creation generates a human-readable title from the parameter values using a small model, replacing the placeholder title. Generation is async and non-blocking; on failure the placeholder stays.

**Blocked by:** Cards in the backlog.

- [ ] A card created with only `issue_id: T3-482` gets a descriptive generated title
- [ ] Title generation failure leaves the card usable with its placeholder title
- [ ] Titles never block card creation or release
